# Provider Interaction Acceptance

This runbook exercises the session-owned form and permission fixtures through the real Basil Validation backend, WebSocket bridge, native `Basil Validation` application, and durable provider-interaction rows. It never uses a user workspace, a provider credential, an external provider, or a normal Basil backend.

Do not run this workflow until the current conversation explicitly authorizes launching the isolated validation application and submitting the named fixture interaction decisions. The control endpoint creates an Agent Task and starts a local process fixture, so source inspection and unit tests do not substitute for this attended validation.

Launch the isolated environment with `scripts/run-basil-validation.sh --session acp-provider-interactions --reset-session --keep-open`. Read `~/Library/Application Support/BasilValidation/sessions/acp-provider-interactions/control-token` and the backend URL from `session.json`; both values are session-local and must not be copied into logs or source files.

Start the form fixture with `curl --fail --silent --show-error -X POST -H "X-Basil-Validation-Token: <session-token>" "http://127.0.0.1:<port>/validation/provider-interactions/form"` before opening the Agent Task window. It returns the Agent Task id and a workspace rooted below that validation session. Open that exact task through the native Agent Task history only after the fixture emitted its form event; assert that all three strategy cards render from durable state and that the host shows the full form plus Skip and Continue without clipping. Resize the native host to the pre-fix compact height, assert that the prompt and form-detail regions scroll while the action row remains visible and operable, then close and reopen the task before choosing `balanced`. Assert that the recovered form has the same selected state, the task receives exactly one response, and the fixture process exits.

Start the permission fixture with `curl --fail --silent --show-error -X POST -H "X-Basil-Validation-Token: <session-token>" "http://127.0.0.1:<port>/validation/provider-interactions/permission"`. Open its exact Agent Task id and assert that the provider permission overlay identifies the local validation fixture. Approve `allow-once` in one isolated session and select the rejection option in a fresh isolated session; assert the durable interaction records the selected option before the provider receives its response, and assert each fixture process exits.

For each native scenario, capture fresh macOS accessibility evidence before acting and a screenshot when the visual overlay or recovered form is evaluated. For the form, assert a visible inner inset between every card and the inline-card border, 8px-scale separation between option cards, a single separator between the option group and clarification area, a clear 12px-scale separation before the action row, the standard overlay shadow and inset treatment, and a stable visible action row when either the prompt or provider form must scroll. Record the Agent Task id, provider-run id, interaction id, status and revision before and after the decision, client-visible state, and the process or fixture cleanup result. Stop if any login, macOS permission, real provider, external sender, account prompt, or other consequential boundary appears.

After the application exits, verify that the session root contains only session-owned files and use the next explicitly authorized `--reset-session` launch to remove it. The session must not be recorded as successful if the backend event was emitted without a matching rendered native state, if recovery required a second response, or if a pending interaction remains after provider-process termination.

Package 6 local web preview is a separate isolated-fixture run. Launch with `scripts/run-basil-validation.sh --session local-preview-package-6 --reset-session` only after the current conversation explicitly authorizes starting that isolated application and responding to its local-server approval prompt. Open `validation-local-preview`, confirm the HTML artifact shows both preview actions, run the static path without a process, then run the server path through the setup form and one explicit approval. Assert the lifecycle summary, Stop preview, native-close teardown, current-or-fallback feedback URL, snapshot status, console evidence, and `network_evidence.policy = not_captured`. Do not use the workspace owner’s active Basil app, conversation, or live task.
