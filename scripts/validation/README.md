# Basil Validation

`scripts/run-basil-validation.sh --session live-preview-audit` launches a separate local `Basil Validation` application and a separately owned loopback backend. It never starts, stops, or reads the normal Basil backend’s port file.

Pass `--synthetic-transcription-audio` for native transcription acceptance. The runner creates a session-owned spoken WAV fixture, and only that validation app replays it through `AudioCaptureService` at the microphone-buffer boundary. This preserves native hotkey, first-buffer, stop, WebSocket, transcription, paste, clipboard-restoration, and immediate-restart behavior without depending on microphone permissions, physical speakers, headphones, or the system input/output route. Normal Basil and validation sessions launched without this flag continue to use their normal hardware capture path.

Pass `--enable-companion` to start the live Meeting Companion runtime, which the validation app otherwise leaves disabled. Use it for Companion checks such as the evaluation record, research, follow-up actions, audits, and the detached-window rail. Checks that record audio or call a real model still need your explicit authorization first.

The session lives at `~/Library/Application Support/BasilValidation/sessions/live-preview-audit`. Its synthetic home, SQLite database, fixture artifacts, backend log, client log, process identifiers, probe, and control token stay beneath that directory. Passing `--reset-session` explicitly removes only that named validation session before launch.

The runner seeds completed, partial, failed, Markdown, text, source-code, HTML, live-PDF, local-web-preview, and three-run historical Agent Task fixtures. Use the Validation menu to open the real Agent Task history, the focused multi-run Agent Task fixture, the static HTML preview fixture, the local-server preview fixture, or the real Basil Board. The app uses production windows, native bridges, WebSocket delivery, previews, menus, and approval UI; only automatic/background behavior that could conflict with normal Basil is suppressed.


The session copies only local provider configuration and API-key files into its own synthetic home. It does not copy normal task history, recordings, databases, UserDefaults, or Keychain entries. Cloud authentication that is not represented by an imported validation credential remains unavailable rather than mutating normal credentials. Existing external-action and approval gates remain active.

To run the full local-preview validation suite, launch `bash scripts/run-basil-validation.sh --session local-web-preview-e2e --reset-session --keep-open`, then run `osascript scripts/validation/accessibility_smoke_test.applescript "$HOME/Library/Application Support/BasilValidation/sessions/local-web-preview-e2e"`. The suite uses only `fixtures/documents/local-preview` beneath that session as its server working directory. It opens the static fixture, requests its token-gated mutation, submits fixed preview feedback through the rendered React handler, and verifies the automatic screenshot and console marker in `local-web-preview-evidence.json`.

To run Package 5B run-history acceptance independently, launch `bash scripts/run-basil-validation.sh --session package-5b-run-history --reset-session --keep-open`, then run `osascript scripts/validation/run_history_acceptance.applescript "$HOME/Library/Application Support/BasilValidation/sessions/package-5b-run-history"`. This runner consumes only the detached multi-run fixture, writes `run-history-focus-state.json`, does not invoke a model, provider, preview server, or external system, and leaves five screenshots beneath that session’s `screenshots` directory.

To run Package 5C managed-history acceptance independently, launch `bash scripts/run-basil-validation.sh --session package-5c-managed-history --reset-session --keep-open`, then run `osascript scripts/validation/managed_history_acceptance.applescript "$HOME/Library/Application Support/BasilValidation/sessions/package-5c-managed-history"`. This runner mutates only its session-owned managed-history fixture through the existing validation endpoint, opens the mounted review workspace, and invokes its existing Restore handler through the validation-only bridge because WKWebView does not expose that control to Accessibility. It verifies the durable rollback record and reopened state, invokes no model, provider, preview server, or external system, and leaves three screenshots beneath that session’s `screenshots` directory.

To run Package 6A local-preview server acceptance independently, launch `bash scripts/run-basil-validation.sh --session package-6a-local-preview --reset-session --keep-open --force-approval-prompts`, then run `osascript scripts/validation/local_preview_server_acceptance.applescript "$HOME/Library/Application Support/BasilValidation/sessions/package-6a-local-preview"`. The `--force-approval-prompts` flag rewrites only that session's own isolated `preferences.json` copy to require a live approval prompt for the local-preview server-start command, with no whitelist match, while auto-approving the model's own incidental read-only inspection commands (`ls`, `cat`, `file`, `echo`, etc.) so they never compete with the server-start command for the single pending-approval slot the backend tracks per agent task — it never touches the operator's real preferences. This runner keeps the shared `AgentTask History` widget open on the `validation-local-preview` fixture task (the only surface that renders the Approve/Deny overlay), denies the first server-start request and asserts a denied session with no process or PID, approves a second request and asserts the exact command/cwd/host/port/loopback-URL and a running session, submits feedback against the running server-preview fixture and asserts the resulting follow-up's screenshot provenance and completion, stops it and confirms the loopback port closes, starts and reaps a second sequential session against the same fixture identity, and reopens after that stop to confirm a fresh session starts rather than reusing the stale one. It invokes no model, provider, or external system, and leaves four screenshots beneath that session's `screenshots` directory.

For subjective review, select `Live PDF preview`, open its artifact in the task tray, then run the smoke script or call the same token-gated mutation endpoint. The inline and detached previews should update without reload or polling. Use the normal UI for any manually initiated workflow. Stop at any authentication, permission, approval, external-message, payment, or other consequential boundary.

The suite opens the local server fixture using only `python3 server.py --host 127.0.0.1 --port 43123`, waits for the visible approval control, and verifies loopback startup, artifact-event refresh, and shutdown after closing the preview. It then performs one isolated direct follow-up with the first installed local reasoning model and first enabled API/custom reasoning model. Those two calls may consume local compute or provider quota and use only copied validation credentials; no normal task history, workspace, capture, or external recipient is used. The runner stops at an authentication, permission, unexpected approval, external-send confirmation, or disallowed tool boundary. The resulting structured report is `full-local-preview-validation.json` beside the session-owned evidence JSON.
