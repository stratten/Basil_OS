# Changelog

User-facing changes to Basil, newest first. Each website release has a section named for its version, such as `## 1.0.0`, whose bullets become that release's in-app update notes. Changes on `main` that have not shipped in a website release are listed under `## Unreleased`, and those bullets also appear in the notes of the rolling `main-latest` repository build.

Write one bullet per line, starting with `- `, in plain language for people using the app. Do not use `<` or `&`, because the update notes are rendered as HTML. When cutting a website release, rename `## Unreleased` to the new version and add a fresh, empty `## Unreleased` above it. Version 1.0.0 is the first public release, so its section summarizes what Basil does as a whole; the changes recorded during private development are kept in [docs/pre-release-history.md](docs/pre-release-history.md).

## 1.0.0

- Basil is a local-first AI assistant for your Mac: run a model on your Mac, or use your own Anthropic, OpenAI, or Google key, any OpenAI-compatible endpoint, or Basil Cloud where it is available, and no account is needed for the first two
- The Basil Board is your main workspace: a single Home input sends each request where it belongs, Chats keeps ongoing conversations, Agents holds your tasks, and To-Dos tracks work that takes more than one sitting
- Dill answers a question or drafts and rewrites text in a single step from a hotkey, by typing or by voice, and keeps your saved outputs so you can refine, edit, copy, or save one as a writing example
- Paprika is the agent: it works through multi-step tasks from a hotkey, shows its progress, uses your files, browser, and desktop, asks before anything consequential, and can be scheduled, paused, resumed, and followed up with notes
- Paprika can change part of a local text file, or several files in one step, by exact replacement with a verified result for each file, and it recovers when a document was changed by one of its own commands or in some other way, instead of refusing to edit it
- A follow-up shows the whole thread of a task, including when you reopen the results window while it runs, starts with an empty request box until its own request arrives instead of showing the previous one, and clears any follow-up you had started typing once another has been sent, including by voice
- Each run shows an honest result: a task is never left on "Verifying the outcome" after it has been verified, a tool call that failed and was then redone successfully does not make a run read "Partial result", and the outcome check reads a long answer in full instead of reporting it as cut off
- The run timeline names the connection and the call, such as "Gmail: search_threads", and a step whose tool reported an error reads "Failed:" instead of "Completed:"
- Connect Gmail directly through Google's Gmail API, with one Google sign-in and the `gmail.modify` permission, and Basil can search and read your mail, write drafts, label and archive, move messages to Trash, send a draft, and save an attachment into the task's workspace folder without ever replacing an existing file
- Every Gmail action that changes your mailbox asks for your approval first, with a plain description such as the sender and subject, there is no permanent delete because Trash keeps a message for 30 days, and Basil does not undo mailbox changes you make yourself while it works, restoring mail from Trash or Spam only when it moved that same message earlier or you asked for that restore
- Gmail drafts that Basil writes sound like you, using your usual greetings, phrases, and writing samples for that recipient, reply to everyone on the original message as Reply All does in Mail unless you ask for the sender alone, contain only the new reply text instead of the quoted thread, and land in the same conversation
- Adding or editing a Gmail connection lets you choose, on a separate page before signing in, between the direct Gmail API and Google's hosted Gmail server, which only works for Google Cloud projects enrolled in Google's Developer Preview Program, and switching never asks you to sign in again
- Settings, under Connections, checks with Google that a Gmail sign-in still works and reports which mailbox and permissions it found, shows "Last used successfully" for each connection, shows the checked and call log times in your local time zone following your Date and Time choice, and colors each tool's approval policy green for Always allow, yellow for Always ask, and red for Never allow
- Adding, replacing, checking, or removing a connection never asks macOS for permission to read your Basil account from the Keychain, because connection tokens are handled separately from the account sign-in
- A scheduled task can be tied to one or more of your connections, such as Gmail, from its own Connections field, every run is told to use exactly those accounts and lists them in its own view, and a run that cannot use one stops and reports the error instead of falling back to Apple Mail
- When you have a Gmail connection, Basil uses it for mailbox changes such as archiving, labeling, and moving messages to Trash, which is faster and needs no approval to take over Mail's windows, and it can still use the Mail app, for example to open drafts there for review and sending
- Apple Mail archiving and moving takes the message out of the inbox as the Archive button and dragging to a folder do, confirms the result before reporting success, asks first to take over Mail's windows, and identifies emails by their permanent Message-ID so a message is still found after Mail syncs or another agent moves things around
- Scheduled runs start exactly once at their start time, and Basil's background service does not freeze while an agent task works and you dictate at the same time, nor fail to search your records during a meeting when two searches start together
- Capture any screen or window for text recognition and visual questions, dictate with live transcription, or transcribe an audio file, with a history you can replay and retranscribe and replacement rules applied before text is pasted
- Notetaker records your meetings and calls with a live transcript, then improves the transcript, labels speakers, and writes summaries, decisions, and action items, and Meeting/Call Detection can prompt you or start a recording for you
- The Companion sits beside a live transcript with notes, answers, topics to watch for, and research in the folders and files you attach, which you can add even after the meeting ends, and a to-do or agent task it suggests starts only when you approve it
- Teach Basil about you with a profile, writing examples, memories, and skills, and connect other tools through MCP and ACP, with approval controls you set for every command, connection, and external action
- Your history, recordings, transcripts, and settings are files on your Mac, your own API keys are kept in the macOS Keychain, and Basil is open source under Apache-2.0
- Make it yours with built-in color palettes and your own saved themes, the Setup Assistant, the Permissions window, and Settings open with the same blueprint reveal as Basil's other windows, and updates arrive in the app, signed and checked before they install
- Notetaker no longer crashes the backend a few minutes into a live meeting when the microphone and system audio are both being transcribed.
- Live Notetaker transcription now always uses the fast Base model or a streaming provider, so changing your saved transcription model only affects retranscription and dictation.
- Notetaker no longer fills the live transcript with a repeated phrase when the speech model gets stuck in a loop.
- If your microphone goes silent after you switch audio devices mid-meeting, Notetaker now notices within a few seconds and reconnects it on its own. If it cannot, it says the microphone is unavailable and offers Retry microphone.
- Retranscription now keeps transcript times in step with the recording timer after a gap in capture, such as a device switch or a pause, so the improved text lines up with the live transcript.
- Settings now lists connections alphabetically by provider so accounts from the same service stay together, and Check Status for All checks every connection instead of one at a time.
- A task waiting on a scheduled follow-up check now has a Stop checking button, and archiving a task cancels its scheduled checks so they can no longer fire later and bring the archived task back into the main list.
- A detached task window now keeps the task title under its window title while expanded, so several detached windows can be told apart.
- Answering an approval request no longer briefly reports that the saved input request is no longer resumable when the task has in fact already resumed.
- The spinning ring around an in-progress agent step now turns more slowly.
- An unselected agent row now says what the task is waiting for, such as Token needed, Approval needed, Input needed, or Your turn, instead of always saying Approval needed.
- You can now ask the agent to connect a service that gives you a token or API key, and finish the setup without opening Settings. Paprika shows the same kind of overlay it uses for command approval, naming the website the token will go to, and you can edit the connection's name and description there so you never have to rename it in Settings and can connect the same service more than once under different names. The task thread keeps a record of the request, that you entered a token, and whether the service accepted it, without showing the token. Basil saves the token in your Keychain and checks that the service accepts it before the agent continues. The token is never typed into the chat, so the agent and your conversation history never see it, and canceling the overlay saves nothing. If the service gives you a ready-made setup prompt for agents, you can paste it into the chat and the agent uses only the server address and name from it.
- Asking the agent about a meeting now returns the meeting's analyses without the full transcript, and long transcripts arrive in pages instead of all at once. Before, a meeting with a long transcript could bury its analyses or overwhelm the conversation; the agent can now read just the summary, pick an older analysis, or page through the transcript as needed.
- The agent can now attach files from your computer to Gmail drafts, including documents it created itself, by naming the file instead of writing out its contents, so attaching a PDF no longer needs the Mail app as a workaround. Basil refuses files from credential and system folders, files over 25 MB combined, and paths that do not exist, refuses a draft that would be completely empty, and a draft is still never sent without your approval.
- Your API keys, sign-in, and connection tokens now live together in one protected Keychain item that only the Basil app opens, so macOS asks for Keychain access once per launch instead of separately for each saved key and token. Keys you saved with an earlier version move into that item the first time you open this version, and Basil removes the old per-key items. If the Keychain item cannot be opened, for example because you chose Deny, Basil tells you and leaves the item untouched instead of replacing it.
- The countdown ring that shows a voice request is about to end now drains smoothly instead of ticking, the recording timer ring moves smoothly too, and the ring now disappears the instant you start speaking again instead of lingering until your next word is transcribed
- A voice request started with the wake word now ends two and a half seconds after you actually stop speaking, however busy your Mac is, instead of sometimes starting to process while you were still talking: Basil now follows your voice directly with a voice activity detector and counts the silence in the recording itself, so quiet speech is no longer mistaken for silence and a slow transcription can no longer shorten the pause, a capture with no speech now ends after about eight seconds, and the status reads "Finishing..." instead of "Processing..." while it is still listening
- Scheduled runs in the floating Scheduled runs panel now show their real result and clear themselves a little while after they finish, instead of staying stuck on "Working on the task" or "Verifying the outcome": a finished run was cutting itself off while it lined up its next occurrence, so the panel never heard that it had finished. The panel also now settles any run the backend stops listing as active without telling it, instead of leaving it stuck
