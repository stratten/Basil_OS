# Changelog

User-facing changes to Basil, newest first. Each website release has a section named for its version, such as `## 1.0.0`, whose bullets become that release's in-app update notes. Changes on `main` that have not shipped in a website release are listed under `## Unreleased`, and those bullets also appear in the notes of the rolling `main-latest` repository build.

Write one bullet per line, starting with `- `, in plain language for people using the app. Do not use `<` or `&`, because the update notes are rendered as HTML. When cutting a website release, rename `## Unreleased` to the new version and add a fresh, empty `## Unreleased` above it. Version 1.0.0 is the first public release, so its section summarizes what Basil does as a whole; the changes recorded during private development are kept in [docs/pre-release-history.md](docs/pre-release-history.md).

## Unreleased

## 1.0.4

- A local server can now come with a setup recipe, so Basil can install what it needs, download or build its files, run it, and tell you when it is waiting for you, all from Settings or by asking Basil to add it. Basil's own code names no particular program: the recipe lists the programs to install and every download address and checksum, or the source address, exact commit and build commands, and you approve exactly that on one card. Each program Basil would install, such as Go, asks for its own approval. A download that does not match its checksum is deleted, and a build uses only the commit named. In Settings the server's row shows each step, with Install, Prepare and Cancel buttons that say exactly what they will run, and when the program needs you to scan a code with your phone, the code appears in the row. Ask Basil to check on a server and it can say what is happening and what you need to do next, and a recipe that failed can be corrected in place without losing the server's saved secrets.
- An AppleScript that Basil runs now always asks you first, even if an older approval you saved looks similar. Previously a saved approval from before scripts were made impossible to remember could approve a completely different script without showing you a card. When Basil sets up a server that depends on a program started by hand in Terminal, it is now told to register that program with Basil so it starts and stops with the app, and the same note appears when it reviews an existing server.
- A new opt-in setting, "Have a separate model review commands, and skip the approval when it is confident they only read", under Settings, Permissions, Command Execution Security, so you stop approving the same harmless commands dozens of times in one turn without Basil keeping a list of safe programs. It is off by default. When it is on and a command would otherwise ask, a separate model call looks at the command alone, never your conversation and never the agent's explanation of why it wants to run it, and the command is handed over as untrusted text so wording inside it cannot talk the reviewer into a verdict. Only a confident answer that the command reads and changes nothing, locally or in any service it talks to, runs it without asking. A command the model thinks changes something, is unsure about, or cannot be reviewed (the model is unavailable, takes more than 30 seconds, answers in an unreadable form, or the command is very long) still asks, and the approval card then says what the reviewer concluded. Blocked commands, high-risk commands, and automation scripts are never decided by it. Each review adds a second or so and uses your default reasoning model, so with a paid API model it costs a model call per command that would have asked. The backend log records every verdict with its confidence, model, and time.
- Each task now has an "Auto-approve" switch next to the model picker, in the box where you start a task, in the follow-up box, and while a task is running, for the times when approving every command one by one is too much friction. Turn it on and Basil approves the commands that task asks to run, including any already waiting, without asking you. It applies to that one task only and turns off when Basil restarts. It overrides Safe Execution Mode and "Always prompt", but it never approves a command Basil blocks outright, a change that gives Basil new access or trust, anything inside Basil's own protected files, or a connected tool, which keeps following that tool's own permission. Turning it on shows a confirmation that says what it does, because every command that task runs after that is unchecked by you. Turning it off needs no confirmation.
- A script no longer asks again for commands you have already approved and remembered. Basil used to compare a remembered approval only with a whole command, so a script that chained several commands, which is how agents usually write them, never matched anything you had remembered and asked every time. With the read-only auto-approval setting on, Basil now looks at each command in a script on its own, and runs the script without asking when every command in it is read-only or one you remembered. Anything new in the script, a command substitution in a remembered command's arguments, a redirect to a file, a high-risk command, or a blocked one still asks.
- The "Basil asked to run" cards in the conversation no longer show a one-line preview of the command in the middle of each card. Each card shows the agent's explanation and a "Show command" button, and the whole command opens in place, with the same height animation as the other expanders, when you click it. The approval windows themselves are unchanged.
- The command approval window's command preview now has the same background and text color as the command in the "Basil asked to run" card in the conversation, so it is clear they are the same command when you open the one in the conversation. The risk badge moved to the right of the window's title, which removes the row it used to take, and the "Add a note for the agent" button now sits close to the note it opens.
- The command approval window says less and says it once. A command that can never be remembered shows one sentence by the buttons with the reason, instead of the agent's recommendation, a notice that Basil overrode it, and "This approval applies to this run only" all saying the same thing. When a command can be remembered, the agent's recommendation now sits under the "Remember this choice" box it is about, not inside the explanation box.
- A run that is waiting on you now keeps its thread scrolled to the end the way a working run does. Before, a command approval or question that arrived was added below the fold unless you happened to be scrolled to the end already, and opening a run that was in progress could leave you at the top of its current turn. The view now follows the end while content is still loading or animating in, and stops following as soon as you scroll up.
- A task that is waiting for a command approval no longer drops back to looking like it is running every few seconds while the window refreshes. The steps in the run rail used to briefly show a running step with a clock and then fold back to the approval's question mark each time.
- A task that has just finished no longer flashes "failed" for a few seconds before turning "completed". Basil first checks a result with a quick mechanical test that calls a run failed whenever any step went unrecovered, even if the answer is complete, and a model then reviews the result a few seconds later. The task window used to show the quick check's "failed" until the review landed. It now shows the answer as a neutral result that is still being verified, and turns red only if the review confirms the failure. The task's stored status still reads failed during those seconds, so a window reopened inside that gap can still show it.
- When several command approvals are waiting at once, the card no longer shows the list scrolling past underneath the "See work so far" and "Stop task" row. The card is now a fixed frame with the title and that row held in place, and only the list of approvals between them scrolls.
- Refreshing a task window can no longer cancel a command approval or fail the task that is waiting on it. A refresh that landed just as a new approval was being created took it for one left over from a restart, canceled it, and marked a task that was still running as failed, which left you with an approval you could no longer answer. A refresh now only reads: approvals left over from a restart are still retired when Basil starts, not from the task window.
- Agents are no longer slowed to a crawl by a long conversation. Every update to a running agent task used to rebuild the search entry for its whole conversation, which meant reading every earlier turn, including large timelines and attachments, and rewriting it all into the search index while holding the one database write slot. In a conversation of a couple hundred megabytes that took about six seconds per update, and three agents at once spent most of their time waiting in line. The search entry is now rebuilt when a turn finishes, fails, is canceled, or stops to wait for you, not on each update while it works, and updating a task's summary no longer loads its full history. A new conversation is searchable by its first request at once, while what a turn produces, and a follow-up's text, are added when it stops, and earlier turns of the same conversation stay searchable meanwhile.
- The conversation search index no longer stores a copy of every earlier turn inside every later turn. Each follow-up carried the full results of all the turns before it, and the search entry included all of those copies, so an entry grew with the square of the conversation's length and some reached hundreds of megabytes. Only repeated text is left out. If a copy holds something that the earlier turn's own record no longer has, it is still indexed, once, and file names and everything each turn produced itself stay searchable.
- Basil now tidies its main database without holding up startup. Search entries built the old, oversized way are rebuilt in the background after Basil is already running (the longest conversations first), resting between entries so your own work is not slowed, and picking up where it left off if you quit first. A write-ahead log that a burst of work left large is trimmed at startup, and the log is capped at 64 MB afterward. At the first launch after the rebuild has finished, and only if at least a tenth of the file and 256 MB are reclaimable and the disk has room, Basil does one full rewrite of the database file to give that space back and switches the file to a mode that returns free space in small slices on later launches. That rewrite can take a few minutes, the startup status says so, and it happens once. A new database is created in that mode from the start, so it never needs the rewrite.
- The backend log now records where a slow agent run spent its time. Each model call logs how long the model took, how long Basil spent preparing the conversation first, and any time lost to failed attempts and retry waits. Each tool call logs its duration, including any wait for an approval. A writer that has to queue for the database for more than a quarter of a second logs who it was waiting behind, and a writer that holds the database for that long logs whether the time went to statements, the commit, or sitting idle with the write open, along with the size of the write-ahead log and a one-minute summary. The per-run timing summary and the approval wait times were being dropped from the log file before, and now appear in it. So do the messages from the several hundred backend modules that named their own logger, which never reached the log file at all, so the log is noticeably longer than before.
- A read-only shell command that stores a value in a variable for later (for example `f=$(ls | head -1); echo $f`) no longer stops for approval just because of the assignment. Storing text changes nothing, so the assignment is accepted when the name is a plain lowercase variable and the value is plain text or a `$(...)` that is itself read-only. Names a shell or program reads (`PATH`, `HOME`, `IFS`, `LD_PRELOAD`, zsh's `path`, and similar), a variable set for a single command (`A=1 ls`), and `export` still ask, and a stored value still cannot become a command name or an option to `find`, `sed`, or `git`.
- In Settings, turning off the last API model provider no longer makes the whole API models section disappear. The providers stay visible, drawn with a dashed border while they are off, with a note saying API models are off, so you can see why and turn a provider back on. A provider that is off can be opened to look at its models. The transcription card stays visible the same way, though its models are listed only while both switches are on.
- The "Everything" setup no longer starts the Voice Listener by default. It is still offered, with its warning about reacting to sounds that are not you, but it starts unticked and runs only if you tick it. Setup now says so in the summary at the top of the review.
- The GitHub sign-in code is now copied to the clipboard as soon as it appears in Settings, and the hint says so only after the copy has succeeded. It replaces whatever was on the clipboard, and the Copy Code button is still there.
- Hey Basil wake-word detection now uses one new model, trained on both pronunciations and on far more varied speech, so ordinary conversation starts a capture much less often. The two earlier Hey Basil models are retired.
- Setup now saves your place as you go, not only when you choose Skip for now. If you close the window at any point after choosing your thinking model, Basil offers to pick up where you left off, with your to-do list, the model you chose, how you like to work and a short summary of what was covered. Nothing expires, and you see a note when the saved session is three or more days old. Choosing Start from the top forgets the saved session.
- The to-do list in setup is easier to follow. A short introduction and a legend explain it, Done and Skip for now say what they do, you can click an item to ask Basil to do it next, and the item Basil is working on right now is labeled Working now. Finished and skipped items are easier to read. You can open and close the list by clicking anywhere on it, and its button stays in the same place.
- A task you start during setup now opens in a pane beside the setup window, and the floating task window has a handle you can drag it by.
- The model step in setup marks the models you have turned on, and says that the pick is only the setup default and can be changed in Settings. The introduction to Working Together no longer promises how long it takes.
- When you bring in what another assistant already knows about you, you can now add screenshots of that text instead of copying it out by hand. Basil reads the text from the pictures with the model you chose, and says so plainly when that model cannot read images.
- Setup notices the apps installed on your Mac, and Basil offers to help with the ones it actually can.
- Connections can now include a local server that runs on your Mac. Basil can set one up from a repository address you give it, using the same approval cards as any other command it runs.
- A local server can now come with a background program that Basil keeps running for it. Add one in Settings under Connections with Add Connection and then A program on this Mac, or ask Basil to add one. Basil picks a free port for the background program, starts it when Basil starts or the first time it is needed, restarts it if it stops, and stops it when Basil quits. Keys and tokens the program needs are typed into Settings and kept in your Keychain, so Basil's agent never sees them. Each program shows whether it is running and has Start and Stop buttons.
- In Settings, Permissions has a new Your Data and Uninstall page. It says where Basil keeps your files, which permissions it has, and how to remove only the app or only your data.
- Choosing Settings from the menu bar while the Settings window is already open no longer redraws it, so you stay on the page you were reading. Opening Settings to a particular page still goes straight there.
- In Settings, Connections shows one line saying what is connected and whether anything needs attention, the Add Connection button always keeps its full label, and a failed connection now shows the reason Basil's background service gave instead of a generic error. Canceling a GitHub sign-in no longer reports an authorization failure.
- If Basil's background service is slow to start, the menu bar says so, the setup splash keeps saying it is still starting, and a leftover Basil process from a force quit or crash no longer blocks the next start.
- Meeting Detection and Activity Capture, when set to start with Basil, now keep trying until they are running, instead of giving up after one failed start, and they never start when you have turned them off.
- Pressing the text size shortcut while Basil is still starting now takes effect once your settings have loaded, instead of being lost.
- A recorded meeting's transcript no longer keeps a repeated phrase, such as the same word twenty times over a quiet stretch, when the recording is finished.
- A task's earlier turns can no longer be listed twice, which could leave copies of the same follow-up in a chain that only went away when you reloaded.
- The scheduled task form is grouped into Task, Tools, and Schedule. Create Schedule and Save changes now say what is missing when they are dimmed, and each run in the run history shows how long it took.
- Basil now recognizes a blocked command such as rm when it is started through env, nohup, xargs, find -exec, timeout, and similar words, and the approval card warns about it wherever it appears in the command.
- Starting a new request from the sidebar no longer risks being folded into the task you had just tried to follow up on, which could show copies of that task's earlier turns in the new request until you clicked away and back. In the "Input required" card, choosing the selected option again now clears it, so you can answer in the other field instead.
- The approval prompt is lighter. The Stop task button now has the same red outline as the Stop button in the main window, the note to the agent starts as a small Add a note link, and for a connected tool the extra warnings appear only once you tick Always allow, in a single message under the checkbox. A finished task now opens at the very bottom of its history instead of the top of its latest request.
- The scheduled request screen is easier to read and use. Every field has a label, the run history shows the full formatted result with a Show more button instead of raw text, a request's status appears once, the weekday pickers and switches match the rest of Basil, and there is one clear main button. Connections now appear as wrapping chips with their own icons, and the app filters in Activity Monitor and Memory Creator use the same chips. A connection shows the icon its server provides when it has one, and otherwise a built-in icon for GitHub, Linear, Slack or Gmail, or a plug.
- The setup question "When should I check with you?" is now two questions, because the answers were never exclusive. "Before you act for me" chooses between asking before sending, changing or deleting anything and skipping routine confirmations. "When something is unclear" chooses between asking you a quick question and making a sensible assumption and telling you. You can now combine, for example, skipping routine confirmations while still being asked when something is unclear.
- The model downloads in setup now show each model's kind as a badge beside its name, in purple for voice models and orange for thinking models. A model that was already on the computer before setup began says "Already on this computer" instead of "Ready", and the text for a failed download is easier to read.
- The run overview rail in the task widget now scrolls when a run has more steps than fit, and it follows the step that is in progress or waiting for you instead of cutting off the bottom of the run. Its steps also arrive faster, so the last step of a long run no longer appears seconds after the first.
- In a long run, the run overview rail now folds stretches of uneventful steps into one green ring with a number, so a run with dozens of approvals and questions no longer needs the rail to scroll. A step that has just finished stays visible as its own circle for about a second and then folds into the number above it, which ticks up. Steps that failed, were denied, timed out, are waiting for you, are in progress, or carry a document are never folded, and the last step stays visible. - While a task is still working and a document is open beside it, the run overview strip now stays on the far right edge of the window, with the document between it and the main area, instead of sitting in the middle. Thin divider lines separate the main area from the document and the document from the strip.

Quick changes such as hover and fade states take 150 milliseconds, and movement and resizing take 400 milliseconds, so the app feels more uniform. The two expanding-height animations that took half a second now take 400 milliseconds, and the countdown bar still moves at a steady pace.

- Basil now reads the shell commands an agent wants to run with a real shell parser instead of splitting them into words by hand. A command that only looks around is recognized more reliably, and a command that quotes, escapes, or nests its parts can no longer hide a program Basil never allows, such as rm, from the safety checks. That program is now also caught when it sits inside a substitution, a loop, a condition, or a nested shell command.
- Basil no longer stops to ask about a read-only shell command just because it checks that a program exists with `command -v` or stops early with `exit`. A command that filters a saved tool result with jq, written the way the assistant usually writes it, now runs without an approval card. A survey that counts things with `echo $(find ... | wc -l)` and tidies names with a plain `sed 's/old/new/'` also runs without a card now, because Basil checks the command inside `$(...)` on its own and accepts it only when it is read-only and sits in an `echo` or `printf`. Anything else that hides a command inside `$(...)` or backticks, including inside double quotes, where it used to look read-only, still asks, and `sed` forms that can write a file or run a command still ask.

- Selecting text next to a switch, such as a sentence in Settings or in the setup learning step, no longer flips the switch when you let go of the mouse. Clicking the switch or its label still works, and switches now show the pointing hand over their label.
- In setup, if confirming a saved API key for the thinking model failed, the model step said "Selected. Finish confirming below." but gave no way to try again. Choosing "My own API key" again now retries the confirmation.
- Turning the voice listener off and back on no longer risks a phantom "Hey Basil" from sound that was heard just before it was turned off. Basil now clears what it had heard once listening has fully stopped, and again before it starts listening.
- When Basil's background service was slow to start, hotkeys and the menu's voice listener, activity capture and meeting detection states were never set up for that session, because Basil gave up waiting after 30 seconds. It now keeps checking until the service answers.
- A second question from the assistant in the same task could fail to appear. The task showed "Your turn" but there was no question to open, and it only came back after you closed and reopened the widget. Every question now gets its own identity when the assistant asks it, so a later question is never mistaken for one you already answered.
- A long question from the assistant, such as one with a big block of code to review, no longer pushes the answer options, the Other box and the buttons out of the bottom of the card where they could not be scrolled to. The question text scrolls on its own and the answer area and buttons always stay in view.
- The buttons on command approvals and on questions from the assistant are tidier. Approve, Deny, Continue and Skip are now small icon-only buttons the same size as the Send button, with Approve in soft green and Deny in soft red, in the same style as the Pause and Stop buttons. Hover over one to see what it does. The Cancel button on approvals is gone, because for commands it did exactly what Deny does. An approval can now be minimized with "See work so far", like a question, so you can look over what the assistant has done before deciding. A Stop task button on the approval ends the whole task, the same as Stop in the header. The buttons now sit in the same order everywhere: tools such as "See work so far" and Stop on the left, then the decision on the right with the negative one first and the positive one last. Yes/No questions are now a choice between Yes and No with a single Continue button, and anything you type in the Other box is sent along with your selection, so a yes with a caveat or a no with instructions reaches the assistant intact. Short options such as Yes and No now sit side by side instead of each taking a full row, and Skip now uses the familiar skip-forward symbol.
- Every recorded meeting now gets a readable transcript file, `transcript_interleaved.md`, saved in the meeting's folder under `~/.basil/meetings/`. It holds the whole call with the microphone and the system audio interleaved in the order they were spoken, grouped into turns with a timestamp and a label above each one, in the same layout as the Export button in the analysis window. The labels say which recording a line came from, not who said it. Basil writes the file when a recording stops, when an analysis finishes, and whenever post-processing improves the transcript, and it rebuilds the file from the recordings when the assistant asks for it, so it always matches what is on disk. The assistant is given the file's path whenever it opens a meeting, so it can read or file a whole call exactly as the Export button would, instead of piecing the layout together itself.
- A meeting that has just ended is now collected into the assistant's memory as soon as the recording stops, instead of waiting for the next timed pass, which could be up to a quarter of an hour away. The history and retrieval tools also gained the refresh option, so a search for something that finished moments ago collects it first.
- The assistant can now refresh its memory before searching your history. A meeting or task that finished a few minutes ago used to be invisible to it until Basil's periodic collection pass ran, so it could tell you the call was not recorded yet. When you refer to something that just finished and it is missing, the assistant now runs one collection pass first, which uses no model tokens and takes a few seconds, and then searches again. It never runs more than once every 30 seconds, waits for a pass that is already running instead of starting a second one, and does nothing if you turned memory collection off. The history tool also now tells the assistant that recorded meetings are stored in their own folders on your Mac, so it has a fallback if a meeting still does not show up.
- The setup assistant now uses one consistent type scale. Text runs at the app's normal body size, headings are always larger than the text under them, and the arbitrary bold that appeared on item titles, sizes, status lines and settings paths is gone. The hotkey clash notice now matches the size of the hotkey row it sits in, the "What's on right now" receipt uses the same hairline-row layout as the hotkey list, and the express setup screens line up with the rest of the assistant instead of sitting in a narrower inset column. When you untick the thinking model on the express screen, the progress screen no longer says it "couldn't" set it up.

Basil reads the script itself before it runs and approves it only when every part is a known read-only form: reading files, parsing and searching text, and printing. Anything that writes a file, runs another program, uses the network, or that Basil cannot fully read still asks, and so does a script run in a folder that holds a file with the same name as a Python standard-library module, unless the command uses the isolated flag.
