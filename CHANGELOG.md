# Changelog

User-facing changes to Basil, newest first. Each website release has a section named for its version, such as `## 1.0.0`, whose bullets become that release's in-app update notes. Changes on `main` that have not shipped in a website release are listed under `## Unreleased`, and those bullets also appear in the notes of the rolling `main-latest` repository build.

Write one bullet per line, starting with `- `, in plain language for people using the app. Do not use `<` or `&`, because the update notes are rendered as HTML. When cutting a website release, rename `## Unreleased` to the new version and add a fresh, empty `## Unreleased` above it. Version 1.0.0 is the first public release, so its section summarizes what Basil does as a whole; the changes recorded during private development are kept in [docs/pre-release-history.md](docs/pre-release-history.md).

## Unreleased

## 1.0.2

- In the sidebar, a scheduled task's colored dot now turns the schedule on or off when you click it, and the play button that appears when you hover a row now runs the task right away. Run now also works on a schedule that is turned off, and it leaves the schedule off. If a run cannot start, the row and the schedule's own page now say so instead of showing nothing.
- Approving a connected tool, such as Gmail or Slack, now offers "Always allow" for that one tool on that one connection, instead of a "Remember this choice" box that either never matched again or covered every tool on the connection. Ticking it sets the tool to Always allow in Settings, Connections, where you can change it back. A tool whose name says it deletes or sends something, such as trash or send, or that its connector declares destructive, shows a warning before you allow it for good, and a connected tool's approval now says it is set to ask rather than that the command is not in the whitelist. A connector's destructive marking is picked up the next time its tools are refreshed in Settings, Connections. Connected-tool patterns remembered by earlier versions no longer approve anything, so those tools ask again until you choose Always allow.
- Setup now starts by asking how you want to set up. You can go step by step (recommended), let Basil set things up for you at a comfort level you pick (Cautious, Balanced or All-in), or choose Everything and skip the second question. Before anything changes, Basil shows a plain summary and a list of what it will do, and you can uncheck any item. When it finishes, you get a receipt of what was turned on and what was left alone. Basil first checks your Mac and recommends only downloads that fit it. Proactive Suggestions is never turned on this way. The confirm screen also lists your hotkeys, so you can take a suggested replacement, record your own keys, or keep one as it is before anything is saved.
- Setup now checks whether Basil's hotkeys share keys with a Mac shortcut, a media key or another Basil hotkey. For each clash it suggests keys that do not clash, which you can accept in one click, replace by recording your own keys, or decline. Everything else in setup keeps working if the check is unavailable.
- Importing notes about yourself is now read by an AI model, through the same route you chose for setup, and Basil tells you where the text goes before it is sent. You review a before and after of your profile, Basil keeps a backup, and you can undo the change. Settings, Personalization, Personal Context uses the same importer.
- While an import is read, it now opens in a dialog that shows the stage it is in, how long it has been working, and the model's own thinking as it writes it (or roughly how much it has written, when there is nothing to show), instead of a bare progress bar on the page. The review opens in a dialog too, with the buttons properly spaced and your profile's Now and After stacked at full width. In setup, what you imported now leads the Getting oriented step, and you can continue straight away instead of waiting for it.
- Setup and Home settings now explain every technical term in a sentence, such as API key and the macOS permissions, and each choice says where to change it later. The Home settings switches describe what they do in plain words.
- Every approval card now says what you are approving. Calls to connected tools, such as creating a request in Speakeasy, now show "What this does" above the command: the agent has to explain the call before the card appears, and the explanation is for you only, never sent to the connected service. Cards that Basil raises itself, such as closing out a To-Do, connecting a service, bringing the browser to the front, starting a local preview, or taking over Mail's windows, show Basil's own explanation, labeled as Basil's. A card that still reaches you without any explanation now says so, instead of looking complete.
- The Basil Cloud sign-in window now looks like the rest of Basil. It uses the same card, thin border, dimmed backdrop, and buttons as the window an agent task opens when it needs your input, and the dimmed area now stays inside the setup window's rounded corners instead of spilling past them. There is one Sign in button, a plain link to switch to creating an account, a Cancel button instead of a separate close mark, and ordinary bullets instead of check marks.
- Setup now opens with a Model downloads step. It lists each model Basil uses by its real name (two voice models and the thinking model), with its own Download button and a Download all button right below the list, and you can skip it. If you skip the thinking model, the reasoning step still offers its download under the Local option. The reasoning options now have a square at the right that fills with a check when you pick one, and the colored bars beside the model rows are gone.
- A scheduled run on a chain you are replying to no longer clears the follow-up you are typing. A window that opened or reloaded while the run was already in progress could mistake it for a follow-up you had sent and discard your unsent text. Now only a follow-up you actually send, typed or by voice, clears the text, and runs that Basil starts, or that the window learns about from a live update or from history, always leave it alone.
- Downloading a model no longer leaves a second copy behind. Once a model is installed, Basil removes the duplicate that the download kept in the Hugging Face cache, and deleting a model now also frees its cached files. Nothing is removed if the download fails, so it can still resume.
- Local models are less likely to fail on a Mac with limited memory. Basil now limits how much text a local model holds at once to what your Mac can spare, instead of the largest size the model claims, and if a model still fails partway through a reply it retries once with half as much before showing an error with Show logs, Retry model, and Report a problem.
- There is now a Report a problem button in Home settings and on the local model error banner. It saves a diagnostics bundle with your logs on this Mac, shows it in Finder, and opens a pre-filled GitHub issue. Nothing is sent until you submit the issue.
- The default transcription model is now one that first-run setup actually installs, so Settings no longer shows base as unavailable after setup. Setup also shows the progress of every starter download, and picks a smaller starter model on Macs with limited memory.
- Setup now recommends a larger local model on Apple silicon Macs with 48 GB of memory or more (Qwen3.6-35B-A3B, a 20 GB download), and keeps the 9B model for Macs with less. Nothing downloads on its own, setup still offers the model for you to approve, and the setup assistant can also offer the smaller model if you prefer it for disk space or speed. If your Mac has the memory for the larger model but not the free disk space to download it (about twice the model size while it installs), setup falls back to the 9B model, tells you how much space is free and how much is needed, and strongly recommends freeing that space for the larger model.
- Model downloads now check free disk space before they start, in Settings, in setup, and when the setup assistant downloads a model for you. If the model will not fit, Basil says which model, how much room it needs while it installs, how much your Mac has free, and how much to free up, instead of failing partway through. A retry after a failed download counts what was already downloaded. Setup also tells the assistant to explain a refused download and to re-check your free space after you clear some.
- Searching and reading files no longer asks for approval when it did not need to. Basil recognized a `find` that groups its tests with escaped parentheses as a command that might change something, so a plain search for documents that mention a word asked every time. It now sees that as a read. The same check also now refuses to treat a `find` that deletes files or runs other commands as read-only when it follows a `cd`, a pipe, or a loop, which it previously let through without asking.
- The agent can now search the text of the files in a folder, list files by name pattern, and read a range of lines from a text file without running a shell command. These tools only read, need no approval, skip `node_modules`, `.git`, and similar generated folders and say which they skipped, and report when a limit cut the answer short. The agent is steered to them instead of a shell `find` or `grep` pipeline.
- The setup assistant is easier to follow. It shows which model route is selected and what the confirm button does, says what a Basil Cloud account is for, offers a side-by-side comparison of local models, reminds you that every preference can be changed later in Settings, and shows example answers under the question about what you are working on.
- You can now import notes about yourself from a pasted text or a Markdown, TXT, CSV, or JSON file, in Settings under Personalization, Personal Context, or as an optional part of setup. Basil shows what it found, lets you choose what to keep, saves dated and undated notes as searchable history, offers stable facts as memory suggestions for you to approve, and lets you undo an import.
- Home settings has Quick Presets. Enable everything turns on the voice listener, activity capture, meeting and call detection, proactive suggestions, and their startup options after you confirm. Conservative keeps only hotkeys on. Presets never grant macOS permissions.
- Basil now checks whether its hotkeys share keys with Spotlight, the macOS input source shortcuts, or Siri, and warns you in the Hotkeys settings. Setup has a new step that shows your hotkeys and any conflict.
- Basil's hotkey checks now also look at the macOS Dictation shortcut. A Dictation shortcut on the same keys as one of your hotkeys is reported as a clash, and Dictation set to press a modifier key twice is reported as a possible clash with your double-press hotkeys.
- Setup's Getting oriented step no longer stalls on a local model. A local model that quoted its whole list of agenda items as one string used to get the same rejection over and over, and the step waited on those retries for more than a minute. Basil now reads that quoted list correctly, for the session agenda and for the choosable option cards too, and it tells the model plainly that the session agenda can only be set after you continue. Basil also stops a local model from showing the same observation card twice, and tells it which observation it already showed.
- Setup conversations now keep a local model on the choosable cards. When a local model answers in plain text, Basil asks it once to resend the reply with its options as cards, and to set the session agenda on the first turn. If it still answers in plain text, you see that text as before.
- The fade at the edges of scrolling areas in setup now matches how much content is hidden. A chat that is only a few pixels short of its end no longer dims its last lines, and the fade updates again after an animation finishes.
- The question-mark explanations on the Settings Home tab now use the same tooltip as the rest of Basil. They follow your theme instead of showing a white bubble on a dark background.
- Setup now says that risky actions wait for your approval, that each approval card explains the action first, and links to the guide on how Basil handles your data.
- Agent task controls are easier to reach. Scheduled tasks in the sidebar now show a pause or play button when you hover over them, so you can deactivate or reactivate a schedule without opening it and scrolling down. The Cancel button on a running task in the sidebar now sits a little lower and further right, clear of the open in a separate window button, so the two are harder to misclick. In a task window, hovering the header shows a Pause button, which becomes Resume while the task is paused, to the left of Stop, and the note box now has a Stop button right beside its Pause button, so Stop is in reach wherever you are looking. Stop and Pause now use the same round icons as the note taker.
- Local models now pick the right tool far more often, and finish tasks sooner. The agent's first tool list used to hold only a short menu of tool families, and a small model often chose the wrong family or the wrong tool. It now holds an index of every tool, grouped by family, with each tool's required arguments, so the model can call the tool it wants directly and Basil loads that tool's family on the spot. In a replay of 23 routing cases on an 8B local model, 44 of 46 runs chose the right tool, up from 26 of 46, and each run spent about 23 percent less time in the model. Connected services are still listed first, with the rule that a connected service is the first route for any request it can serve.
- Local models are now steered toward a connected Gmail or other mailbox, instead of the Mail app, when you ask for email without naming the Mail app. Basil's tool descriptions now say plainly that the local email tools serve only the Mail app and Outlook on this Mac, the connected-service tool is described as the route for connected mailboxes, and the tool index leads with a line for your connected mailboxes when you have any. Web pages are also steered to the browser tools instead of AppleScript or the shell, even when a browser is already open. This improves the choice but does not make it reliable on a small local model: in a replay on an 8B local model with nothing on screen, a connected-Gmail request chose the connected service in about 7 of 16 runs, up from none, and Mail app requests chose the Mail app in 16 of 16 runs.
- Local models now remember the long, unchanging start of an agent's request, so each step of a task reads only what is new instead of the whole prompt again. In a test with a prompt of about 6,600 tokens on an 8B MLX model, a follow-up step began answering in about 0.1 seconds instead of about 3.5 seconds. Short side requests no longer push that memory out. Models that run on Basil's original local engine now also keep a larger memory of their prompts, scaled to your Mac's RAM, and Macs with less than 24 GB of RAM leave it off. Set BASIL_MLX_PROMPT_CACHE to 0 to turn the MLX memory off, or BASIL_LLAMA_CPP_PROMPT_CACHE_GB to a number of gigabytes to change the other.
- On Apple Silicon Macs, Basil can now run local models with Apple's MLX engine, which is faster and uses less memory than the previous engine. Basil now recommends the MLX version of a model on these Macs. The original versions stay in the model list, and nothing is downloaded twice unless you choose both.
- Transcriptions you run on demand now use the language you chose in your settings, instead of always detecting the language from the audio. Choose Auto to keep detection.
- Updated the speech and language libraries behind Basil's transcription and local models.
- An agent running inside Basil can now change Basil's own look when you ask, such as "make your UI pink" or "make your text larger". Color, text size, font, and surface changes apply at once, keep text readable, and can be undone. A setting that changes how Basil behaves shows you a card with the old and new value and waits for your approval, and a request nobody answers is declined. Approvals, credentials, and sign-ins cannot be changed by an agent at all. The same tool now reaches most of Basil's other settings, each with the same approval rule, and the Setup Assistant draws its list of settings from the same place. An agent can also list your scheduled tasks and pause one, and open the Settings window on a tab when you ask where something is.
- "Remember this choice" on a command approval now remembers what the card shows. The agent names the part of the command that identifies what it does, such as gh gist view, and Basil accepts that only when it is exactly the start of the command being approved. The card says which commands remembering would approve, and warns when it would approve every use of a tool. Before, remembering gh gist view stored only gh, which approved every gh command, and a bare tool name such as git or gh can no longer be remembered. Settings flags any stored single-command pattern so you can tighten or delete it.
- A remembered command now has to match whole words of the command Basil is about to run, so remembering gh no longer approves a different program that merely starts with those letters. A remembered command is never used to approve a shell command that chains, pipes, redirects, or substitutes other commands, and a remembered command that Basil rates high risk, such as a forced push, asks again.
- Basil's checks for blocked and read-only commands now see every command in a chain, even when the separator is written without spaces. Before, a command such as ls followed by a semicolon and rm inside a shell wrapper could be treated as read-only or slip past the blocked-command check.
- Basil now recognizes more commands as read-only, so asking an agent to look at things stops for approval less often. Added are sort, uniq, cut, tr, diff, jq, shasum, basename, dirname, realpath, readlink, uname, sw_vers, hostname, id, uptime, lsof, pgrep, test, sleep, printf, cd, loops and if statements around read-only commands, git status, git log, git diff, defaults read, and sed with a single print command. Sending error output to the null device, or merging it into normal output, no longer counts as writing a file. Forms that can write a file or change a setting, such as sort with an output file, a second file name for uniq, sed with a write command, git push, and defaults write, still ask.
- An AppleScript that only reads from Mail, Calendar, and similar apps is no longer sent for approval just because it sets a part of a date it created itself, such as setting the time of the current date to midnight before looking up today's events. Setting a part of anything else still asks.
- Agents are now told how to write a read-only AppleScript that collects results, such as a list of subjects from Mail: declare the collecting variable before the tell block, or give it a name like outText. Before, a plain name such as out set inside the tell block looked like an application property, so Basil asked for approval on a script that only reads.
- Sending the backend process the USR1 signal now writes every thread's Python stack to the stall log in the diagnostics folder. Before, a task waiting forever on a lock while the event loop stayed healthy left no trace, so a hang like that could not be diagnosed.
- Fixed an intermittent freeze where a local model task never started. It happened when a new local task began while the previous task's outcome check was still generating: the new task canceled the check, but the canceled check kept holding the local model, so the new task waited for it forever and nothing in Basil reported a problem. The model is now released as soon as the check is canceled.
- Local model calls now log one line when each call ends, with the time to the first token, the prompt tokens read versus reused from the cache, the completion tokens, the decode speed, and how much of the reply was thinking versus the answer. Before, a slow local call could not be traced to prompt reading, thinking, or answering.
- Agents are now told to leave activate out of a read-only AppleScript on the first attempt and to add it only on a retry, and only if the first result came back empty or stale for data they know exists. Reads from Mail and Calendar work with the app in the background, while activate brings the app to the front and forces an approval prompt. Before, the script-writing instructions told agents to include activate whenever the app needed it.
- Agents now start every task with the list of your enabled connections and a rule to try a connection first for any request it can serve, even when the request does not name the service. When several connections of one kind exist and you name none, such as three Gmail accounts and a request for your most recent email, the agent checks each one, compares the results, and reports the newest across all of them with the account it came from. A local app such as Mail is used only when you name it or a connection fails or does not cover the work. Before, the tool catalog told agents to look at connections only when the request named one, so a plain request for the most recent email went to the Mail app and spent minutes on timeouts.
- A command hidden right behind a separator and an open parenthesis, such as a semicolon followed immediately by a parenthesis, is now seen by the checks for blocked and read-only commands. Before, a blocked command such as rm written that way was treated as read-only and was not blocked.
- A follow-up or a new task now always runs on, and records, the model the picker shows, even when that model is also your default. Before, choosing the default sent nothing, so a follow-up could inherit an earlier turn's different model or follow a default you had changed since, and the run never learned which model it was on, which switched off Basil's context-window budget and made context-length messages say only "the selected model". Tasks started without a picker, such as To-Dos, now record the model that applies when they start, the follow-up picker opens on the model the previous turn really ran on, and scheduled follow-ups on older chains stay on that model.
- One oversized answer from a connected service can no longer fill the model's context window. Basil now saves the whole result, shows the agent a short preview and an outline of what is inside, and lets it read one part, search for a value, or open the saved file. Saved results are kept for 14 days and can be read only from the task they came from. Before, a single request lookup returned about 2.5 million characters and stopped the task with "needed more context than the model's window".
- The collapsed task window now keeps you informed about every task, not only the one it was showing. Its bubble shows the processing state while any task is working or waiting for you, and it opens by itself when any task finishes a turn or needs your approval or input, so the new entry near the top of the list is visible. Opening on a finished turn still follows the setting for reopening when a task completes, and it does not switch you to the other task.
- Basil no longer asks you to approve a file command that stays inside the agent's own task workspace. The agent can now read, search, list, copy, move, and create files there with cat, head, tail, grep, wc, ls, cut, sort, uniq, mkdir, touch, cp, mv, pdftotext, pdfinfo, and qpdf without a prompt, as long as every path in the command is inside that folder. Anything that reaches outside the folder, runs a script, or uses a command that is not on that list still asks, and Safe Execution Mode still asks for everything.
- A long task no longer runs out of room as quickly. When a task's history gets close to the model's context window, Basil now has the model write a short record of the earlier steps, keeps your original request and the newest steps in full, and saves the complete earlier history so the agent can search it for an exact value. Older results that Basil trims are now saved in full as well, and the trimmed copy says where, instead of only asking the agent to run the tool again. If the model still refuses a task as too long, Basil now writes that record first and tries again, and only then removes older results, saving each one before it goes.
- Starting a separate task from a running task now works. It was failing with "unavailable right now" because the tool was given a service that cannot start standalone tasks, and the agent is now told not to retry when it truly cannot be started.
- The Copy rich text and Copy markdown buttons now sit at the right end of the Result heading, above the result instead of on top of it, and are easier to see. The copy button on an embedded code block or quote is now the same copy icon instead of the word Copy, and the whole block has a faint tint so it reads as set into the result.
- If Basil's background service stops answering for about a minute, Basil now offers to restart it, instead of leaving you with the message that it isn't responding. Nothing is restarted unless you choose Restart Background Service, and if the service comes back on its own while the offer is open, it is left alone.
- Reading text from screenshots no longer risks freezing the whole background service. Basil now starts the text reader in a way that cannot stall its other work, and it records a native snapshot from outside the service if a freeze does happen, so the cause can be found.
- Opening a long conversation and saving its summary is faster, because Basil now looks up the turns in a conversation by its index instead of reading every saved task each time.
- A command approval card now has an optional note box. Whatever you type is sent with Approve, Deny, or Cancel and reaches the agent in the same turn, so "that file is in Documents" or "approve, but also check the exit code" no longer needs a deny, a pause, and a separate message.
- Files you attach to a note sent to a running task, or to the note on resuming a paused one, now appear in the conversation as file chips, with the file name, a click to open it, and Reveal in Finder, instead of a bulleted list of full paths.
- Memory summaries that were missed because Basil was not running at the scheduled time now run as soon as the background service starts, and a Mac that slept through the scheduled time starts them within about 30 seconds of waking. Before, a missed run waited for the next day. A run that stopped early, for example because no model was loaded, is tried again about every 15 minutes.
- A memory summary that fails because no model is loaded no longer counts against the card's three tries, and the run stops there instead of failing every remaining card. Cards with nothing to summarize, such as a transcription with no text, are now removed instead of being counted as "Couldn't summarize".
- Memory summaries on a cloud model now run several at a time in the scheduled run as well as the manual one, and use a lower reasoning effort than the model's default for chat. Local models still run one at a time.
- Waiting for a specific element on a page now works in Chrome. Before, that wait always failed with an empty reply, so Basil gave up on pages it could have used.
- After a click, Basil now waits for the page to finish loading and reports where it ended up, including the page title, headings, and any error messages, so it no longer acts on a page that has not changed yet or misses a validation error.
- When Basil cannot find an element, it now says what the page shows instead, such as a verification page, and lists similar elements. If a page goes blank while an action is running, Basil no longer repeats the action, because repeating it could submit a form twice.
- Reading a page now skips menus, headers, and footers on pages without a main content area, can continue a long page, and can read back every form field's current value before Basil submits. Basil also marks the site-wide search box so it stops mixing it up with the form it is filling, and it can fill several fields in one step.
- Basil can now read a simple type-the-characters image CAPTCHA with your model's vision and submit it, with two attempts per site before it asks you. Other challenges, such as reCAPTCHA, picture grids, sliders, block pages, and sign-in pages, are always handed to you.
- When a step needs you, Basil can now bring its browser window forward, ask you to finish it, and put your previous app back afterward. This follows your browser foreground control setting: under Background only it tells you which window to open instead, and under Ask before foreground it asks first.
- Basil can now send a few navigation keys to its own browser window to pick from a saved-card dropdown that sits inside a frame from another site. It follows your foreground control setting, never types text, and never reads card numbers.
- Approvals for filling a password or other sensitive field now show their approval card. Before, they reported that no approval channel was available.
- Browser tasks no longer pull your browser to the front to take screenshots. Basil now captures its own automation window directly, even when another app is in front of it or covering it, and it reports a clear error if that window is gone instead of capturing whatever app happens to be on top. Basil also stops raising that window each time it reuses it.
- Your browser foreground control setting now covers more of the ways a script can take over your browser. Scripts that bring a browser forward through System Events, set it frontmost, open it with a command, open a new window, or open a link in it are now blocked under Background only and ask for approval under Ask before foreground, the same as scripts that name the browser directly.
- When another app, such as a WhatsApp call, holds your microphone so that Basil records only silence from it, Basil now notices within seconds and tries to take the microphone back, retrying a few times. If it still cannot, the meeting window shows a warning that the microphone is only delivering silence and that another app may be using it, and it keeps retrying more slowly until your voice comes through again. Before, the recording looked healthy while your side was empty, and nothing told you.
- Files you drop while recording a spoken follow-up now appear in the conversation as soon as the reply is accepted, the same as they do for a first request, instead of only once the final result starts to arrive.
- Dropping a file while recording a spoken follow-up no longer resizes the task window. Before, the window snapped to the small size of the standalone recording panel, which was most noticeable after you had expanded the result.
- Tables now look the same everywhere Basil shows Markdown: task results, the review workspace, the side panel preview, Home and conversation messages, meetings, assistant history, and writing examples all use rounded corners that match the rest of the interface. A number column now stays wide enough for two digits, words are no longer split in the middle, and the side panel preview has padding on the left instead of starting at the edge.
- A question from Basil no longer goes missing while the task says it is waiting for your answer. A window that still showed the task as paused now opens the question, and if a window is ever left waiting without a question, an Input required card appears at the bottom with an Answer now button that loads the question, instead of you having to click away and back or open the task in a separate window.
- Pressing Command-Return in any answer box of a question from Basil now sends the answer, the same as clicking Continue.
- A command approval or question that you answer in one agent task window now disappears from every other window showing that task, instead of staying stuck on the main window after you denied it in a detached one.
- When Basil is waiting for your answer and you have closed the question, the note box now stays at the bottom of the task. What you type there is sent as the answer to the question, and Stop is still available at the top, instead of the task offering no way to reply or interrupt.
- An HTML file opened in its own preview window, or in the document preview beside a Home conversation, now shows the rendered page instead of a blank area, the same as it does in the task sidebar.
- A narrow table column, such as an Inbox column of short names, is no longer squeezed down to one letter per line inside the result of an earlier turn. The wide text columns give up the space instead, so each word in the narrow column stays whole.
- Choosing See work so far on a question from Basil now lets you scroll the task and open its earlier turns and follow-up history. Before, the question's invisible overlay covered the whole task and swallowed every scroll and click.
- Reopening an agent task window while it is waiting for your answer now shows the whole run so far, including the earlier steps and the reasoning, instead of only the request for input.
- When Basil prepares draft emails or messages and stops before sending, its final answer now shows each draft in full, with recipients, subject, and the complete saved body, even when your standing instructions ask for short replies, so you can approve a draft without asking to see it first
- Dropping files or folders while creating or editing a scheduled task now attaches them to the scheduled task instead of vanishing or landing in the follow-up box of the task you had open before, and dropping files right after opening a different task now attaches them to that task rather than the previous one
- When Basil asks you to approve something, such as sending an email, it now shows the exact content in a "Show details" section under the question: the recipients, subject, and full message for an email, or the exact items for a change; approvals show it open, other questions keep it one click away, and Basil is instructed to always include it before anything is sent, posted, or changed irreversibly
- A scheduled task that continues one conversation now starts a new conversation based on the conversation's total length, counting follow-ups you type and follow-ups Basil starts itself, not only the scheduled runs, so a conversation you keep adding to cannot grow without end; the limit is labeled in turns and conversations already past it start over at the next run
- Basil can now start a separate agent task on request, for example when you ask it to split one email's work off so you can carry on with the other emails in the same conversation, and the new task links back to the one it came from
- A rejected request to hand work to a child agent now returns the reason to Basil so it can correct the request, instead of failing the whole turn
- A scheduled task tied to a connection, such as Gmail, still tries that connection first, but Basil may now use another tool, such as a local app, a script, or the browser, when the connection has no tool for a step, is signed out or broken, or keeps failing after reasonable attempts, instead of stopping and handing the step back to you; a call you denied stays denied, and the final report names each step done outside the connection and why
- When Basil searches your Gmail, it is now told that the results are only short previews and to read the full thread whenever an accurate answer, summary, or reply needs it, without stopping to ask you first, so it needs fewer extra turns to draft a good follow-up
- A question from Basil that is waiting for your answer no longer disappears and reappears every 20 seconds or so while Basil's background status updates keep arriving

- Agent tasks now keep a checklist of what still needs to happen as a result of your request and of what Basil or you find along the way, such as a reply to each email in a thread. Done and dropped items stay behind. It is off by default.

It reads each item against the delivered response, the tool results, and what you said, and it marks an item done only when its outcome really happened. Each change is logged in the item's history as an outcome check. The check never overrides an item you last changed, never touches a checklist whose tracking you stopped, and never changes whether the task counts as successful.
